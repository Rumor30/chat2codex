# Session / MCP 设置机制

## 0.2 实际实现

本版实现的是 **复用已登录 Electron profile 的受保护设置助手**，不是“导入一个 token、直接调用私有 Connector REST API”。程序不会导出 Cookie，不修改 2FA，也没有猜测 ChatGPT 私有创建接口。

`bridge/launcher-entry.cjs` 在锁定的上游启动器上增加一个本地鉴权控制入口，只允许固定的身份检查、打开设置、设置助手和退出动作。网页没有 Node 权限，不能把任意 JavaScript 通过接口传进去。账号原有浏览器 profile 与新设置窗口使用同一隔离 session。

`bridge/provision.cjs` 通过明确可见控件识别表单。支持中英文名称、精确 Tunnel ID 的原生选择框、认证方式和工具扫描。识别不明确的自定义下拉框不会仅凭展示名选择；同名 Connector 只显示核对提示，不推断它一定指向本项目。

## 提交与恢复

```text
明确配置授权 → 独立登录窗口 → 已授权 Tunnel
→ 打开 Apps 设置 → 识别并准备可确认的表单
→ 扫描工具 → 创建前持久化意图 → 最多提交一次
→ 必要的用户安全确认 → 对所选模型运行真实 MCP nonce 探针
→ 仅该模型进入 Ready
```

创建点击前写入意图。发生超时、窗口关闭或进程退出后，下一次不会直接重复 Create；控制台要求先到设置页核对已创建的服务。未知控件、工具扫描未完成、管理员或安全确认，都会停留为可见的“需要操作”状态。

身份检查复用上游已使用的只读 `/api/auth/session` 端点。身份原文和其中可能包含的 token 不离开 Electron；本地控制接口只返回随机盐哈希。检测到登录主体/返回的工作区身份变化、或启动器重启后，旧验证结果失效。这里不声称这个端点一定暴露所有组织切换方式，因此实际账号/工作区切换仍是上线验收项。

## 验证边界

设置状态机有单元测试；完整表单动作已通过真实 Chromium 的**合成 DOM**测试，包括禁止提前创建、未知 Tunnel、禁用的安全控件和重复创建保护。控制台通过真实本地 HTTP 网关操作测试。它们不使用真实 ChatGPT 账号。

尚没有在用户授权登录环境中观测、验证完整当前 ChatGPT Connector 创建流程。因此不保证当前真实网页控件全都匹配，也不保证用户只点一次就配置完所有权限。手动设置入口始终保留；没有服务端 entitlement 时停止，不尝试绕过。

“某项目可用 session 开启 2FA”不能作为这里接口可用的证据。未来要增加私有 API 模式，需要先确认真实请求、额外认证、组织策略、幂等性和重复创建恢复，并单独记录端到端测试。
